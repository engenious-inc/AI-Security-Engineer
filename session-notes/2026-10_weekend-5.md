## Day 9: Recon on a new target, model fingerprinting, scripted direct injection and a home-built LLM judge (~2h51m)
Low turnout; one attendee was listen-only, one said they would leave after an hour, and one joined about
an hour in. The vocal group was about five students. Flow:

1. Opening: a recruiter's job post (Jaime). Jaime shared a role that had reached out to him: a "regular"
   test automation engineer title (Playwright, Cypress, Selenium) whose duties now include AI evaluation:
   confidence-threshold assertions, semantic similarity checks, rubric-based validation, golden benchmark
   datasets and evaluation harnesses, hallucination and groundedness testing, regression detection across
   model and prompt versions, and AI test coverage across accuracy, robustness, bias, safety, performance
   and reliability. Hybrid, quoted at $89k-157k. A student whose day job is setting quality bars asked
   whether the course would cover how to set thresholds and golden dataset size; Jaime: build the
   harness and dataset, run a first pass to get a baseline, then agree "what good means" with
   stakeholders. Vladimir: bars come from business, legal and "do not harm humans" needs per domain,
   starting from how public leaderboards score models; he said this deserves its own block.

2. Homework show-and-tell (~20 min). A student had already built an NLT adapter for RedCell in her own
   repo, with NLT-specific strategies, and showed a run with one finding; her open problem was how to
   test an agent that acts within role permissions (admin vs customer accounts) rather than a plain chat
   model. Another student had an adapter running against NLT but still using the Mercy Bank strategies,
   her first time doing anything like this; she wants a workflow that keeps the coding assistant "under
   control." Tips traded: ask for summaries; scope the request and say "do nothing else"; have ChatGPT
   write constrained prompts for Claude with explicit do-not-touch rules, a read-only review first, then
   show the diff; write a "project handoff" summary before a chat's context window runs out. Vladimir:
   he asks Claude Code for a handoff `.md` file at each logical milestone and starts a fresh session from
   it, mainly to check the agent is still on plan.

3. Lab setup demo (Jaime, ~20 min, much of it live troubleshooting). Jaime pushed a UI refresh of the
   ticketing app that morning. He runs the app's model on a rented GPU pod (RunPod, Ollama, an RTX GPU;
   shut down overnight to save credits), pulled Phi-3 mini, pointed the app's `.env` at the pod URL and
   restarted Docker Compose. The app returned errors until a student spotted a stray forward slash in
   his `.env`. Then a hanging Burp intercept. He presented the struggle as normal.

4. Exercise 1, manual recon and fingerprinting (~20 min breakout). Inputs: the NLT intake questionnaire
   and the ROE, plus recon goals and sample probing prompts. Recon goals: which model and its
   characteristics; is there RAG and what can be learned about it; can the system prompt or details of
   it be found; how deterministic it is (temperature); context window size; tools or agentic
   capabilities; rate limits and quotas; handling of special characters and encoding. Jaime demoed Burp
   Suite with FoxyProxy in Firefox: scope `localhost:5000`, intercept a chat message, send it to
   Repeater, edit and resend; reuse cookies and the conversation id across Repeater tabs for multi-turn;
   forward to release the response to the UI. He pointed out that the response payload alone shows the
   app has a RAG component. Burp was presented as "not a must" (Postman works) but as traditional
   pen-testing vocabulary worth recognising in interviews. Debrief: the group mostly spent the room
   getting setups running (a Burp/FoxyProxy port conflict for one student; another had not installed
   Burp; another was still configuring Mercy Bank and had not realised the Week 5 app is the
   `ai-security-chatbot/` folder in the same repo; Docker Compose up/down commands are missing from the
   docs, which Jaime agreed to add).

5. Frameworks (Jaime, before the second break). **OWASP Top 10 for LLM Applications (2025):** mapped to
   the remaining exercises: prompt injection (direct and indirect), sensitive information disclosure,
   improper output handling, excessive agency, system prompt leakage, a RAG-related item,
   misinformation (hallucination). **MITRE ATT&CK** (adversary tactics against traditional IT, cloud and
   enterprise networks) and **MITRE ATLAS** (the AI counterpart): Jaime walked the threat matrix (e.g.
   reconnaissance: active scanning, autonomous recon) and its maturity filter (feasible, demonstrated,
   realized). A worked mapping of OWASP categories onto NLT's attack surface (the first row, LLM01
   prompt injection) was shown as an exercise students can continue.

6. Exercise 2a, model fingerprinting with "LLM map" (planned 10 min). An open-source tool Jaime compared
   to nmap: it asks eight queries, the tester pastes each into the target chat and pastes the answer
   back, and it predicts the underlying model from a set of pre-trained profiles. Rationale: knowing the
   model (and whether it is an older, less-protected version) points to known weaknesses. Students
   cloned it into a separate `tools/` folder, created a Python virtual environment, installed
   `requirements.txt`, and fixed two issues with their coding assistant. Jaime's own live run failed and
   he shelved it mid-exercise; he later got it working with a specific Python version. Results: one
   student's run guessed Phi-3 mini when the target was Mistral 7B; another's correctly guessed Mistral
   7B; a third automated the loop in-session with Codex.

7. Exercise 2b, direct prompt injection, manual then scripted (~20 min breakout). A CSV of 25
   direct-injection technique categories, compiled by Engenious while building the course, not available
   online: instruction override, debug-mode activation, role switching, multi-step extraction,
   reverse-psychology framing, system-tag spoofing, verbatim-repetition requests, continuation-style
   attacks, model-specific instruction-format tricks, session-reset framing, and simulation / "test
   mode" framing. Task: try some by hand in the UI, feel the pain of tracking them, then write a Python
   script that reads the CSV, sends each row to the ticketing chat, captures the response and writes a
   results CSV. Framing: "let's pretend no framework existed," since some employers will not allow
   open-source tools. Sample result columns: id, technique, repeat number, request number, response
   time, prompt, response, HTTP status, timestamp.

8. Exercise 3, an LLM-as-judge injection classifier "from scratch" (~20 min breakout). Students asked
   their coding assistant to build a script that reads the results CSV and adds three columns: injection
   label (succeeded or not), confidence, and reason. Jaime showed a short judge prompt and his own
   example row, and linked it to promptfoo's LLM rubric. Debrief: one student's responses contained
   newlines, which broke parsing and then Excel, so she added handling in the prompt and a small
   CSV-to-Excel converter. Two students used Mistral 7B (local) as judge but different target models
   (Mistral 7B vs Granite 3.1), and their success labels differed; one reran because some models missed
   hits others caught. A student asked how to guard against a judge that hallucinates: use stronger,
   newer judge models, review every row as a human in the loop (only 25 rows), and rerun with a second
   judge model to compare ("trust but verify").

9. Feedback round. Asked whether the "struggle first" approach helps, a student said yes: the exercises
   tell her what to build since she has no cybersecurity background, but "you can't run fast on this if
   you don't know how to prompt Claude ... set up your repo." Another asked for more guidance on
   automating recon and documenting evidence, and on how much detail a formal report needs. Jaime said
   he is holding back scripts so the answers are not spoiled, planning to commit them "probably Sunday
   night": RAG, obfuscation and encoding injections, narrative injections, rate limiting, temperature
   probes, plus a notes `.md` showing how each test was documented.

10. Close. Day 10 continues hands-on (indirect prompt injection through the UI was named) and Igor will
    cover "next steps"; Jaime said the cohort is officially five weeks and this is the final week, and
    that Igor is considering a continuing "incubator" (a bi-weekly or similar meetup so skills are not
    lost).

Career content: the recruiter job post; a student's worry that AI-evaluation roles demand strong Python.
Jaime: in interviews ask whether the company allows AI coding assistants, point to your GitHub as
